# v0.7.0 — Multi-target compatibility

Baseline: v0.6.6, PR #8, master commit `a9d5296aef9f1254b3012bfbe13229f03ff5073b`.

User requirement (2026-11-26): continue supporting .NET 8 and 9 while adding .NET 10 and 11. All seven projects are multi-targeted. CI selects the matching stable SDK, builds the selected TFM and runs the existing stress, V06 and browser E2E tests separately for each runtime. No changes to public APIs or communication code.

Invariants: singleton broker spanning HTTP request and SignalR circuit scopes; session isolation; bidirectional delivery; genuine IndexModel.OnDataChanged subscription on the persistent SSE request; C# DOM commands through scoped RazorDomBridge in the existing core project; generic JS dispatcher; optional original JSInterop callback independent of SSE; observer retained for diagnostics, no polling.

EFHelper uses EF Core 8.0.34 / 9.0.23 / 10.0.15 / 11.0.0 respectively. BlazorComponents uses the target's ASP.NET Core shared framework instead of a fixed .NET 8 Components.Web package. Playwright remains pinned to the baseline version.

Follow-up (not included): evaluate typed SSE APIs on .NET 10+, ensuring identical wire contracts and a compatible implementation on .NET 8/9; evaluate observer retention and ordering separately. Existing SSE reconnect and subscription cleanup remain unchanged. No release or merge before CI verification. Compatibility with .NET 8/9 does not restore Microsoft servicing for those runtimes.
